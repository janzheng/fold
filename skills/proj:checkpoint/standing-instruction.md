# Project Workflows

During project work, read relevant existing lessons/gotchas before repeating an
operation. After a meaningful task, experiment, or decision, and before a handoff,
use `proj:checkpoint` to reconcile affected task/brief status, retain useful run
evidence or lessons, and surface the next action. Skip trivial/no-change passes.
Keep the agreed outcome in view: flag material scope growth, explain what can
ship without it, and park optional work with a concrete reason to revisit it.
Brainstorm naturally; save uncommitted ideas only when useful or requested.
This is active-session behavior, not background monitoring or permission to
commit, publish, deploy, or expand the user's scope.
